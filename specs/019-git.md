# Git in a session

## Overview

Git is optional: a session with no repository runs, checkpoints and
hands off the same way ([[034-checkpoints-and-rewind]]). When a session
names repositories, the runner delivers them into the machine and the
agent uses plain git inside it, reads and pushes, like a developer
would. The agent's token for the git host never enters the sandbox:
Cella's egress gateway substitutes it on requests to the git host, and
the runner rotates it before it expires. The git host's authorizer
decides every push by ref: an agent writes only its own branches and
never a protected one, and landing on the default branch stays a
person's action. Every commit carries trailers naming the session and
the agent version.

## Current state

v0.7.0 had no git support in the loop; its adversarial engine read a
diff with a local `git` binary and left with that engine. The retired
hosted service had no working git credential path: its sandbox client
used a Cella grant mode that nothing served. There is no push tool in
this design and none is borrowed: an agent pushes with `git push`, and
the boundary is at the git host.

## Design

### Repositories as inputs

A session names zero or more repositories in its resources as
`{"type":"repository","url","ref"}` ([[004-session-log]]). At the
session's first claim the runner delivers each one into the machine:
the first into the working directory, each further one into
`<workdir>/<repository name>`. The session works on the branch
`agents/<agent>/<session>`, created from `ref`, or from the
repository's default branch when `ref` is absent; `<agent>` is the
agent's name and `<session>` the `ses_` id. On a Cella machine the
sandbox's egress allowlist includes each repository's host
([[009-machines]]).

### Plain git in the sandbox

Inside a Cella sandbox, git is the image's own and the agent runs it
through `bash`: clone, fetch, commit and push work as they do for a
developer. The sandbox never holds the credential. The agent's token
for the git host is a Cella Secret scoped to that host
([[018-credentials-and-secrets]]); inside the sandbox it is a
placeholder, and Cella's egress gateway puts the real value on requests
to the git host only. The runner replaces the Secret's value with a
fresh token before the current one expires, so a long session keeps
working and no token outlives its session by more than its own
lifetime. On the host the person's own git configuration applies
([[009-machines]]).

### Ref rules at the git host

The git host's authorizer decides every push by ref, with the agent's
permissions and the session's scope ([[018-credentials-and-secrets]]):

| Ref | An agent's session may |
|---|---|
| `refs/heads/agents/<agent>/*` | create, update and delete |
| `refs/topos/checkpoints/<session>/*`, its own session only | create and update ([[034-checkpoints-and-rewind]]) |
| a protected branch, the default branch included | nothing; landing a change there stays a person's action |
| any other ref | what the agent's permissions grant, never more than its initiator could do |

Origo applies these rules in its own authorizer when it is the git
host; another git host applies them through its own branch protection.
A push the rules refuse fails in `git`, and the agent sees the git
host's refusal as a command error.

### Attribution

Every commit a session makes carries two trailers, and the runner
sets the author for the session:

| Trailer | Value |
|---|---|
| `Topos-Session` | the `ses_` id |
| `Topos-Agent` | the agent id and version, `agent_<ulid>@<n>` |

The author name and email are the agent identity's
([[018-credentials-and-secrets]]); on the host they stay the person's.
The runner sets them through the environment of the machine's
commands, and a `commit-msg` hook installed in each delivered
repository adds the trailers when a commit lacks them.

### The git cache

With `TOPOS_RUNNER_GIT_CACHE` set, the runner keeps a bare mirror per
repository URL in that directory, fetches into it before a delivery,
and delivers from it, so a runner that serves many sessions of one
repository fetches its history once. Mirrors are fetched with the
session's credential and never shared across credentials that may not
read the same repository: a mirror is keyed by the repository URL and
used only after the session's own fetch of the refs it needs succeeds.
Unset, each delivery clones directly.

### Limits

| Limit | Default |
|---|---|
| repositories per session | 8 |
| a delivered repository's size | 2 GiB; a larger one is cloned with `--filter=blob:limit=10m` |

### Error codes

| Code | Meaning |
|---|---|
| `repository_unavailable` | a repository could not be delivered: not found, not readable with the session's credential, or over the limits |

## Not in this spec

Credential custody and the Secret the gateway substitutes
([[018-credentials-and-secrets]]); checkpoints
([[034-checkpoints-and-rewind]]); worktrees on the host
([[009-machines]]); the git host's own implementation of the rules.

| Criterion | Test that proves it | State |

| A push to a protected branch is refused by the git host and reported to the agent as a command error | `TestPushToProtectedBranchRefused` | not built |
| The runner replaces the token before it expires, and a push after the first token's lifetime succeeds | `TestTokenRotatedBeforeExpiry` with a short token lifetime | not built |
| Every commit of a session carries `Topos-Session` and `Topos-Agent` | `TestCommitTrailers` | not built |
| Two sessions of one repository on one runner fetch it once through the git cache | `TestGitCacheFetchesOnce` | not built |
| A session with no repository runs and checkpoints the same way | `TestSessionWithoutRepository` | not built |
