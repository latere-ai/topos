# Git in a session

## Overview

Git is optional: a session with no repository runs, checkpoints and
hands off the same way ([[034-checkpoints-and-rewind]]). When a session
names repositories, the runner delivers them into the machine and the
agent uses plain git inside it, reads and pushes, like a developer
would. The agent's token for the git host never enters the sandbox:
Cella's egress gateway substitutes it on requests to the git host, and
the runner rotates it before it expires. The git host's authorizer
decides every push by ref: an agent writes only its own branches and
never a protected one, and landing on the default branch stays a
person's action. Every commit carries trailers naming the session and
the agent version.

## Current state

v0.7.0 had no git support in the loop; its adversarial engine read a
diff with a local `git` binary and left with that engine. The retired
hosted service had no working git credential path: its sandbox client
used a Cella grant mode that nothing served. There is no push tool in
this design and none is borrowed: an agent pushes with `git push`, and
the boundary is at the git host.

## Design

### Repositories as inputs

A session names zero or more repositories in its resources as
`{"type":"repository","url","ref"}` ([[004-session-log]]): at most 8,
each an `https` URL that names its host and holds no credential, and a
`ref` that is a branch, a tag or a commit, never git's option or range
syntax ([[015-api]]). An agent names the repositories its sessions work
in as `spec.repositories`, each `{url, ref}`, checked the same way when
the agent is applied ([[003-manifest]]); a session whose create names no
repositories takes those of the agent version it pins, and one that
names any takes its own alone. When the session's first machine exists
the runner delivers each one into it: on a Cella machine, which is
opened on demand, when the first tool that acts on it opens the
sandbox; on the host, at the first claim ([[009-machines]]). The first
repository goes into the working directory, each further one into
`<workdir>/<repository name>`, the last segment of its URL without
`.git`. The session works on the branch `agents/<agent>/<session>` in
each of them, created from `ref`, or from the repository's default
branch when `ref` is absent; `<agent>` is the agent's name and
`<session>` the `ses_` id. A plain `git push` publishes that branch:
each repository sets `push.autoSetupRemote`. A repository already there,
as a delivery the runner restarted finds it, is configured and not
cloned again. The delivery is recorded before the `session.machine` of
the machine, so its context block names the branch and its instruction
files and skills are read from the delivered checkout. On a Cella
machine the sandbox's egress allowlist includes each repository's host
([[009-machines]]).

### Plain git in the sandbox

Inside a Cella sandbox, git is the image's own and the agent runs it
through `bash`: clone, fetch, commit and push work as they do for a
developer. The sandbox never holds the credential. Its token for the
git host is minted for that one destination, within the session's
scope, marked workload `sandbox`, and without the git host's flagged
actions ([[012-permissions-and-approvals]]); it is a Cella Secret
scoped to the git host's host and path ([[018-credentials-and-secrets]]),
a placeholder inside the sandbox, and Cella's egress gateway puts the
real value on requests to that destination only. The runner replaces the Secret's value with a
fresh token before the current one expires, so a long session keeps
working and no token outlives its session by more than its own
lifetime. On the host the person's own git configuration applies
([[009-machines]]).

The runner's delivery and the agent's own git reach the git host with
the sandbox's git configuration, which sends the placeholder of the git
host's Secret as a bearer to the installation's git host,
`TOPOS_ORIGO_URL`; it is set when the sandbox opens, before any
repository is delivered, and the Secret is applied, minted and rotated
there ([[018-credentials-and-secrets]]). Neither the delivery's script
nor the log carries the placeholder or the value. A repository on
another host is cloned without a credential, as a public one is, until
a Connection covers its host.

### Ref rules at the git host

The git host's authorizer decides every push by ref, with the agent's
permissions and the session's scope ([[018-credentials-and-secrets]]):

| Ref | An agent's session may |
|---|---|
| `refs/heads/agents/<agent>/<session>` and `refs/heads/agents/<agent>/<session>.*`, its own session only | create, update, force-update and delete |
| another session's `refs/heads/agents/` branches | nothing; a session is known by the token's binding, so one session cannot rewrite another's work, whoever started it |
| `refs/topos/checkpoints/<session>/*` | nothing from the sandbox; the runner creates them with its own token, never updates one ([[034-checkpoints-and-rewind]]) |
| a protected branch, the default branch included | nothing; landing a change there stays a person's action |
| any other ref | what the agent's permissions grant, never more than its initiator could do; force-updating or deleting one is a flagged action, asked through the step-up ([[012-permissions-and-approvals]]) |

Origo applies these rules in its own authorizer when it is the git
host; another git host applies them through its own branch protection.
A push the rules refuse fails in `git`, and the agent sees the git
host's refusal as a command error.

### Attribution

Every commit a session makes carries two trailers, and the runner
sets the author for the session:

| Trailer | Value |
|---|---|
| `Topos-Session` | the `ses_` id |
| `Topos-Agent` | the agent id and version, `agent_<ulid>@<n>` |

The author is the agent: its name, and the email
`<agent name>@agents.topos.invalid` until the agent identity carries an
address of its own ([[018-credentials-and-secrets]]), the same author
an isolated thread's commits carry ([[013-threads-and-subagents]]); on
the host they stay the person's. The runner sets them as each delivered
repository's own `user.name` and `user.email`, which survive a restart
of the runner and reach every command, and a `commit-msg` hook installed
in each delivered repository adds the trailers when a commit lacks
them.

### The git cache

With `TOPOS_RUNNER_GIT_CACHE` set, the runner keeps a bare mirror per
repository URL in that directory, fetches into it before a delivery,
and delivers from it, so a runner that serves many sessions of one
repository fetches its history once. Mirrors are fetched with the
session's credential and never shared across credentials that may not
read the same repository: a mirror is keyed by the repository URL and
used only after the session's own fetch of the refs it needs succeeds.
Unset, each delivery clones directly.

### Limits

| Limit | Default |
|---|---|
| repositories per session | 8 |
| a delivered repository's size | 2 GiB; a larger one is cloned with `--filter=blob:limit=10m` (not built: every repository is cloned whole) |

### Error codes

| Code | Meaning |
|---|---|
| `repository_unavailable` | a repository could not be delivered: not found, not readable with the session's credential, or over the limits. The call that opened the machine answers it and a `session.error` names it; the machine stays, recorded, and the session's next calls run on it |

## Not in this spec

Credential custody and the Secret the gateway substitutes
([[018-credentials-and-secrets]]); checkpoints
([[034-checkpoints-and-rewind]]); worktrees on the host
([[009-machines]]); the git host's own implementation of the rules.
